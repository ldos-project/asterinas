# Deploying a trained model in a kernel policy

The policy is Rust source compiled into a `no_std` kernel, so a trained model is deployed by
writing its parameters into the policy as constant arrays, and evaluating it with plain loops. Have
your training code print the Rust text of the arrays so the numbers are exact. This compiles and is
what the kernel's own learned policies do:

```rust
const N_IN: usize = 3;
const N_HID: usize = 4;
static W1: [[f32; N_HID]; N_IN] = [ /* generated by your training code, row-major */ ];
static B1: [f32; N_HID] = [ /* ... */ ];
static W2: [f32; N_HID] = [ /* ... */ ];
const B2: f32 = 0.3;

/// The model's prediction for one feature vector, e.g. the cost of one option.
fn infer(x: &[f32; N_IN]) -> f32 {
    let mut hidden = [0.0f32; N_HID];
    for j in 0..N_HID {
        let mut acc = B1[j];
        for i in 0..N_IN {
            acc += x[i] * W1[i][j];
        }
        hidden[j] = if acc > 0.0 { acc } else { 0.0 }; // ReLU
    }
    let mut out = B2;
    for j in 0..N_HID {
        out += hidden[j] * W2[j];
    }
    out
}
```

Build each option's feature vector from what the policy observes when it decides, call `infer` once
per option, and choose by the predictions. A decision tree can be deployed the same way, as nested
`if`/`else` on the features. Some things to keep in mind:

- `f32` arithmetic (`+ - * /` and comparisons) works. There is no math library, so avoid `exp`,
  `tanh`, `ln`, `powf` and `sqrt`; ReLU and comparisons are enough.
- The policy runs on every decision, so keep the model small (tens to a few hundred parameters)
  and the feature computation cheap.
- The features must come from what the policy can observe when it decides, and must be computed
  the same way in your training code as in Rust, or the model sees different inputs than it
  trained on.
